## Active production flow

`hl-copytrader serve` creates the loopback FastAPI app. The continuous controller previews/starts an explicitly configured plan and derives a stable engine directory from plan identity. Direct CLI runs enter `scripts/run_continuous_fleet.py`.

`continuous_runner.py` performs the bounded startup catalog bootstrap, validates profiles/accounts, opens per-signer action journals and per-slot runtime state, builds the network driver, emits status/metrics and owns top-level shutdown. `continuous_network.py` owns the source, market and action WS sessions plus reconcile/closeout tasks. Pure reducers fold source/follower/account and public market events. `continuous_runtime.py` turns attributed source changes into desired follower state and reduction/increase decisions. `continuous_executor.py` serializes a signer lane; `ws_actions.py` signs/posts IOC actions; `action_journal.py` is the durable truth boundary.

### Durable-state rule

Runtime state belongs on local NTFS under `%LOCALAPPDATA%`, not the OneDrive checkout. Credentials remain in ignored profile files. Do not casually reuse an engine directory after an offline plan identity change, and never bypass signer/generation locks.

## PR #14 repair sequence

### P0 — prevent another exposed fatal exit

- Replace static all-market subscription ownership with bounded/JIT active-market ownership and explicit headroom.
- Make fatal transport shutdown state-aware: stop new increases, preserve journals, reconcile follower truth, and drive bounded reduce-only closeout or loudly preserve a recovery-required state.
- Define one closeout owner; eliminate assertion races between runtime, network driver and top-level runner.
- Add direct tests that reproduce reconnect overlap plus exposed followers.

### P1 — restore correct trading admission

- Allow verified reduce-only convergence even when an older UNKNOWN increase exists; never permit replacement increase ambiguity.
- Verify/provision intended leverage before arming and latch repeated deterministic margin rejection classes.
- Harden exact minimum-notional/full-close behavior at the sub-$10 boundary.

### P2 — trustworthy diagnostics

- Drain/flush final monitoring and action queues before terminal status publication.
- Report source, market, action, reconcile and closeout states separately.
- Preserve terminal reason, outstanding exposure and explicit operator action in a fail-close artifact.

### P3 — economics only after correctness

- Preserve BBO-first IOC pricing and single-flight signer lanes unless new evidence disproves them.
- Define delayed-target and monitoring-loss economics before optimizing latency or throughput.
- REST budget was not the incident cause; normal execution remains WS-first.
